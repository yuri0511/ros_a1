## 修复与实测反馈

- q 为两侧棱柱关节的米制位移，正方向均为张开；内间距为 `0.052 + q_left + q_right`。退出约束仍为每指 8–14 mm，进入退出阶段仍要求 10–14 mm。
- 零力不会保持位置：待机时出现重力导致的不对称漂移；arm2 原释放卸力后越界。新 helper 对两指分别给出有界 effort，目标 12 mm、比例系数 150 N/m、力上限 ±1.5 N。没有设置或篡改 JointState。
- 无持件保持终值：arm1 约 11.88/12.12 mm，arm2 约 12.30/11.70 mm。这是短时仿真测量，不是所有姿态/负载的误差包络。
- 成功轻触轮两指实际接触后 q 约 −1.005/−1.081 mm；释放后校准块观测位置约 `[0.295000,-0.235031,0.745024]` m。原始接触 168 点，均为预期两指—校准块接触；未记录箱壁、双臂相撞。释放后等待接触消失再抬升。
- 相机帧与关节帧可相差 1 ms。标定器现等待真实时间戳对齐，既不改写时间戳，也不放宽 0.2 s 对象新鲜度。
- 标定器使用独立 ROS 执行线程，规划请求不能阻断两指监测/保持。消费端缓冲改为 100，仍保留 50 ms 源时间间隔、0.5 s 新鲜度与独立 `/clock` 检查；增加消费端原始记录。先前一次消费端间断时，独立观察器记录的源消息最大间隔仅 16 ms，不能归为 Gazebo 源发布丢失。
- 接触原始消息实测接近物理更新节奏。逐消息写 JSON 导致观察器积压，曾把持续双侧接触误判为丢失。现原始 CSV 全保留，只将状态快照以约 20 ms 周期写出；未放宽 0.1 s 接触新鲜度。不能把先前的“丢失”直接认定为真实脱爪，也不能把遗漏 −8 N 锁紧认定为已证实唯一物理原因。
- 0.01 rad Pilz 小动作产生重复终点时间 0.2 s，JTC 拒绝。没有删点或修改控制器检查；增加发送前严格时间检查，标定动作改为 0.0123 rad。一般轨迹重复时间问题仍需上游处理。
- 工具回调身份、消息操作码反序列化、模块导入等失败均留档；修正后针对原因复验，不作为机器人失败率。
