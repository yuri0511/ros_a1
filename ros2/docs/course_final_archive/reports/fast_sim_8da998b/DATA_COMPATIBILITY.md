# 数据兼容性和后续离线模型校准

本轮不训练或重训 Q 表，不以 Q 表控制 Gazebo。完整基线为 `8da998b963eed3c70fda076329f04a75c8627ef3`；原 `083a515` 性能数据保留为历史基线，不能混成同一对照组。

## 必须分别保存的四种数据

A=1ms+原等待，B=1ms+事件等待，C=2ms+原等待，D=2ms+事件等待。另按低干扰性能测量/高精度接触验证、实例数量、复测轮次及v1/v2/v3源码版本分开。每轮metadata包含Commit、源代码聚合哈希、步长、等待开关、目标RTF、线程、环境、域和分区；逐件CSV、原始stats和TaskStatus事件保存原始来源。

- **仿真时间**来自消息时间戳、原生Gazebo stats；批次还记录实际墙钟及单项等待的monotonic时长。
- 不把墙钟与仿真时间相减。不用瞬时RTF的简单平均替代时间差分，不将多个实例RTF求和当作产出。
- 不把旧模型的feed/pick/post_pick均值与本轮不同物理/等待配置直接拼接。固定墙钟等待在不同RTF下对应的仿真时长不同，即使都是1ms也可能改变时间分布。
- 接触探针、位姿跟踪本身有开销，精密验证批次的耗时不能代替低干扰性能值；精密批次成功也不能抵消低干扰同配置的失败。

## 可用于校准的内容

通过完整任务与接触核对的配置，可提供同配置的送料请求/生成/视觉到达/推板回位/派发/ZONE_CLEAR/放置/COMPLETED时间、每色与箱格的实际时长、失败尝试与恢复成本、墙钟/仿真时钟关系，以及资源和多实例竞争的影响。`phase-events.csv`保留所有TaskStatus事件；日志保留送料、规划、控制器和等待明细。

这些资料是**重新定义边界并校准模型的原始样本**，不是可直接替换为一组无条件成功均值的训练资料。失败后留在场景中的工件可能干扰后续任务，同一轮后续失败不一定独立。应保留整轮轨迹与失败历史。

仍需明确或另测：

1. 送料必须包括推板回位和安全可派发，不能只计生成至停推进。
2. `ZONE_CLEAR`仍沿用Yuri原实现：竖直抬高完成时发出，手仍在取件点正上方。接触验证只支持已覆盖轨迹组合，不能自动证明任意Q策略重叠轨迹都安全。
3. `COMPLETED`包含尝试回待命。应结合实际`return_standby`控制器结果区分“工件放对”和“机械臂已可接下件”。
4. 逐色/逐箱格样本数量有限，失败、恢复和重叠样本不均，不能用单轮均值宣称长期稳定分布。
5. 原记录器在成功后12个仿真秒回收工件，本轮保持此行为。低干扰位置来自记录器完成时XY（毫米舍入）；高精度位置为回收前最后原生XYZ。本轮不能校准长期在箱中累积/堆叠的物体接触模型。
6. 2ms即使完成8件也不能视为1ms的数值等价；必须一起看接触类别、深度/持续时间、位置偏差、控制器与抓取变化。出现永久失败的配置不得作为已验证高速采样设置。

## 旧 Q 表的地位

`q_feed.py`和调度器Q接口保留，实验配置把三条路径明确置空，日志确认规则调度。外部`dual_arm_rl`、计时JSON和实表没有在本分支内；本次缺资料的4项Q测试不能说明算法错误，也没有用假表替代。

旧Q表对库存、动作/状态格式、路由和策略研究仍有参考价值，但数值依赖旧timing版本。若采用本轮新的等待策略或物理步长，后续应先冻结实际事件边界与数据版本、重新校准timing及异常成本，再训练/验证匹配该配置的新表；不能直接声称旧表对新Gazebo时序仍最优。是否最终部署还需真实Q控制的Gazebo验收，本轮不执行。

HANDOFF中接触验证叙述的`overlap_validated=true`与旧JSON中的false是不同层次。没有擅自改动任何`overlap_validated`或`deployment_ready`字段。缺少实表，不能把规则分拣成功当作Q表已经部署成功。
