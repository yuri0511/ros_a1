# 红箱第4格：支撑接触规划修复（等待一次 Gazebo 复验批准）

## 准确根因

基线为 `662d7ba1978965217c808d745b0252e68dea1c67`。原始证据：
`calibration_runs/C-20261017T102733-3d3e3a/held-cycle.json` 的第一个 `lift_32mm` GetMotionPlan 请求，以及同目录 `held-state-validity.json`。

工件最初是世界物体。该请求的 `start_state.attached_collision_objects` 已包含完整 50 mm 立方体 `retained_calibration_red4`，附着链接为 `arm2_tool0`，仅两指保持原有 touch_links。回放的接触 body type=2，明确为附着物体。

世界障碍之间的支撑接触与机器人附着物体—世界碰撞不是同一语义。附着以后，MoveIt 把工件作为机械臂携带的碰撞几何，严格检查它与 `tabletop_floor_red` 的起始碰撞。测量位姿经过完整关节 FK、工件局部变换及转角计算后，最低角点为 `0.7199999484692642 m`，支撑面顶为 `0.72 m`，相交约 `5.15307358e-8 m`（51.5 nm）。这是非零几何交叠，不能简单称为浮点误差或直接四舍五入。原请求在 CheckStartStateCollision 阶段被拒绝，未发送提起 Action。

## 最小处理范围

1. 有效夹持前不授予支撑接触许可：须有真实双指接触、原 −8 N 锁紧力、原开度/反馈约束、连续夹指稳定观察，以及新增的 native 工件接触传感器证实红箱底支撑接触。
2. 同一完整工件由 WORLD 转为 ATTACHED。Apply ACK 后读取场景，确认世界中不再重复存有同 ID，机械臂仅有一个附着实例；形状、局部变换、全部其他障碍保持一致。并未删除支撑面、箱壁、夹爪或缩小工件。
3. 快照原 ACM，只对 `retained_calibration_red4 ↔ tabletop_floor_red` 对称设为允许。拒绝未知默认 ACM 语义；所有其他条目保留。每次设置和恢复均 ACK+语义读回核对，异常恢复完整原矩阵。
4. 规划完成后独立按 JTC 五次插值，以不大于 1 ms 的间隔检查完整机器人、夹爪和原尺寸附着工件。支撑接触样本单独核验最低点不低于初始实测最低点；非接触状态使用正常 ACM；其他碰撞对始终由 FCL 拒绝。仅使用 64 个 IEEE eps 的计算舍入比较量，未引入毫米级穿透容差。
5. 真实提起时，native 和相机均证实最低点离开支撑后，立即恢复原 ACM。完全出箱和返回上方两段使用正常约束。实际出箱还核对工件及夹爪三部分的最低点高于既有箱沿 0.815 m。
6. 最后的受控接触下降单独短时处理同一支撑对，穿透不能超过起始几何值；运行期 native 深度/最低点不得超出动作前真实观察包络。放回确认后释放，按真实相机位姿转回 WORLD，再恢复原 ACM；不是把支撑对永久加入白名单。
7. floor 接触深度增长、再次异常接触、非目标碰撞、源反馈过期、失去夹持、Action 拒绝/中止或退出不安全，都写入故障记录并暂停本实例。带载异常时先暂停世界，再撤掉夹持命令，避免清理过程主动掉件。

## 与当前阻断直接相关的轨迹修正

离线审查发现，原放回 Pilz 轨迹经 JTC 五次插值会产生约 **0.0637992 mm** 的最大穿透，不能执行。只对最后接触下降改为保留中间路径点、每点静止的有界五次插值；时长只增加，按原 URDF 速度及 YAML 加速度上限乘原 0.2 缩放计算。

另一个末点 IK 误差约 `1.73e-7 rad` 会增加约 19.5 nm 的终点穿透。因此最终命令严格使用本轮原始实测待机于箱底的目标关节值，而非 IK 近似值。没有移动 Gazebo 工件、抬高支撑面或伪造位姿。修正后的完整轨迹重新经过 FCL 与独立支撑面检查。
